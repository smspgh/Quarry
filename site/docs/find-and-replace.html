Find in the current file

Ctrl+F opens the find bar and Ctrl+H opens it with the replace field. If you have a short single-line selection (under 500 characters), it fills the search box, every time: select something else in the document and press Ctrl+F again, with the bar still open, and that becomes the search text. Pressing Ctrl+F while the cursor is in the search box only selects what you typed.

  • The match count updates as you type (it shows "100k+" above 100,000).
  • A multi-line search without Regex is matched literally.
  • In regex mode the replacement can use $1, $2, … and $& for the whole match.
  • Preserve Case (the Aa toggle in the replace box, or Alt+P) matches the case of each replaced text, as in Replace in Files: foo → bar also turns FOO into BAR and Foo into Bar.
  • Find in Selection (the last toggle in the search box, Alt+L, or Find › Toggle Find in Selection) limits the search to the text that was selected when you turned it on; with several selections, to all of them. Those ranges get a faint background and follow your edits. The match count, Enter / F3, Replace, Replace All and Alt+Enter then only see matches that lie wholly inside them. With nothing selected it takes the line the cursor is on (the lines, with several cursors); on an empty line there is nothing to search in, so it stays off. Turning it on with the find bar closed opens the bar without putting the selection in the search box. It turns off when you close the find bar, press Alt+L again, or switch to another document.
  • Related commands: Ctrl+D adds the next occurrence of the selection as a cursor, and Ctrl+Shift+L selects all occurrences.

Clearing a box, and history

These work the same in the find bar and in Find in Files.

  • × inside a find or replace box clears it. It shows only while the box has text.
  • History (the clock icon, or Alt+↓ in the box) lists what you searched for or replaced with before, newest first, with the date and time each was last used. Click an entry, or move to it with the arrow keys and press Enter, to put it back in the box.
    • Find and replace have separate lists. Entries are shared between the find bar and Find in Files.
    • An entry is added when you run it: a search (Enter / Shift+Enter in the box, the Next / Previous Match buttons, or the Search button) or a replace. F3 / Shift+F3 only step to the next / previous match and add nothing, so a macro that repeats them does not fill the history. Running the same text again doesn't add a copy: the entry moves to the top with the new time and its use count goes up, shown as ×3, ×12 and so on. From 10 uses the count is highlighted, a hint that a search you repeat that often might be worth a macro or script.
    • In the list, Delete or the × on an entry removes that entry, and the bin icon clears the whole list.
    • The list is long-scrolling. It shows 100 entries at a time and adds more as you scroll, so a long history stays fast.
    • History is saved to search-history.json in the settings folder and survives restarts. It's read only when first needed, not at start-up.
    • It's unlimited by default. Settings › Search › Find & replace history can limit it to a number of entries instead. Entries longer than 10,000 characters aren't kept.

Find in Files

Ctrl+Shift+F opens the Search panel; Ctrl+Shift+H opens it with the replace field.

Where it searches

ScopeSearches
Current File (default)The active document, including unsaved changes. A large-file tab is searched on disk.
Open FilesThe text in every open tab, including unsaved changes. Large-file tabs are skipped.
Folder / SelectionThe folder open in the Explorer, recursively, or what you last clicked or selected in the Explorer: a folder, a file, or several of each (Ctrl+click / Shift+click). The button reads Folder for a folder and Selection otherwise, and the line under it shows what is searched ("In Quarry\src", "In 3 items: a.txt, src, b.md"). Whole folder goes back to the whole open folder. With several folders open in the Explorer the button reads Folders and all of them are searched ("In 2 folders: site, lib") until you click something in the Explorer; All folders goes back to all of them. Right-click in the Explorer and choose Find in File, Find in Folder or Find in Selected to jump straight here.
Choose…One or more folders you pick.

Find in Files starts on Current File each time Quarry opens. A scope you pick stays selected until you close Quarry. The selected scope is highlighted in the accent colour, so it's clear at a glance whether you're searching the file or a folder. Current File is shown only while a file is open, and Open Files only while tabs are open; until then, the search falls back to the next scope that applies. When the panel is too narrow for the buttons in one row, they wrap onto more rows rather than being cut off, and the Search panel can't be made narrower than 280 pixels, so the search box always has room.

Options

Match Case, Whole Word and Regex are the toggles inside the search box. The rest are under the Filters button (next to the scope buttons), which shows how many filters differ from their defaults:

  • Dot matches newline.
  • Use .gitignore (on by default) skips files ignored by .gitignore, .ignore, .git/info/exclude and your global gitignore.
  • Include / exclude: comma-separated glob patterns such as *.ts, src/** or *.min.js, dist/**. With an include pattern, only matching files are searched. Include / exclude and Use .gitignore apply only to the folder scopes.
  • .git, node_modules and target folders are skipped, unless you give an include pattern.
  • Hidden files are searched. Symbolic links are not followed.
  • Binary files (any containing a NUL byte) are not searched past that byte.
  • A pattern that contains a line break, or any regex, can match across lines. Without Regex, a line break (Ctrl+Enter) matches both Windows (CRLF) and Unix (LF) line ends; in a regex searched on disk, \n is only the LF, so write \r?\n to match either (Current File and Open Files see every line end as \n).
  • Max (results) defaults to 20,000 (adjustable up to 1,000,000). The status line says "(limit reached)" when the limit was hit. A folder search also lists at most 1,000 matches of any one line (a minified file, say); the rest of that line is not listed.

Results stream in as they are found, grouped by file, and you can cancel a running search. While there are results, the Search panel stays docked beside the editor instead of floating, so it doesn't close when you click into a document you opened from it; see Window layout. Long searches show the first 1,500 rows; Show more results adds more.

Each result row shows the match with a few whole words before it (up to three) and the rest of the line after it, so the match is always in view. … marks text left out at the start; a match at the start of a line is shown from the line's first word.

Opening a result scrolls the editor so the whole match is in view. If the match is off to the side on a long line, the editor scrolls sideways to bring it near the left edge, with 10 characters of the line before it, so the text after it shows too; a match near the start of a line is shown from the line's beginning. (With word wrap on there is no sideways scrolling.) Go to Line positions the cursor the same way.

Opening a result highlights every match in that document the same way the find bar (Ctrl+F) does, with the selected match in the stronger colour. The highlighting stays while you move through the results, and clears when you press Escape in the editor, open the find bar, clear the results or run a new search.

Replace in Files

With the replace field shown, each result previews the change: the match struck through, followed by the replacement. Replace All asks for confirmation and then:

  • edits every matching file on disk, writing each file atomically;
  • skips files that are open with unsaved changes and lists them, so your edits are never overwritten;
  • reloads open tabs whose files it changed;
  • refuses files over 256 MB, which you can open in large-file mode and use Replace All there;
  • changes nothing you left out of the results (see above);
  • replaces every match in each listed file, including matches that aren't listed: past the first 500 results of a file, past the 1,000 listed from one line, or past Max in the file where the search stopped. The confirmation says so: how many aren't listed when that's known ("300 of them are not listed…"; with Current File / Open Files also the exact number past Max), and "More matches that are not listed may also be replaced" when it isn't (a folder search that reached Max or the per-line limit). Files the search never reached are not changed;
  • keeps each file's encoding: a file is decoded as it would be when opened (its BOM, else the detected encoding, such as Windows-1252 or UTF-16), replaced, and written back in the same encoding with the same BOM;
  • leaves a file unchanged if its encoding can't store the result (for example, a Chinese character in a Windows-1252 file) or if it doesn't decode cleanly, and says why;
  • reports per-file failures under the file ("Replace failed: …").

Preserve Case (the Aa toggle in the replace box) matches the case of each replaced text: replacing foo with bar turns FOO into BAR, Foo into Bar and foo into bar. Mixed case such as fOO gets the replacement as typed. The preview in the results shows the result.

In regex mode the replacement follows JavaScript's rules in every scope, on disk too: $1 … $99 or $<name> for groups, $& for the whole match, $` and $' for the text before and after it, and $$ for a literal $. A reference to a group that doesn't exist, and ${name}, stay as typed. In plain-text mode, $ is literal.

With the Current File and Open Files scopes, Replace All edits the open documents in the editor instead of the files on disk. Each document can then be undone with Ctrl+Z, and the changes are saved when you save. A document you edited after the search is skipped and listed, as a file changed on disk since the search is; search again to include it.

Undo Replace in Files

Before a Replace in Files changes a file, Quarry keeps a backup copy. Find › Undo Replace in Files, or the Undo link in the Search panel's status line, restores them byte for byte.

  • Only the most recent Replace in Files can be undone.
  • The backups and the undo are kept when you close Quarry, so a replace can still be undone after a restart. They are cleared when the next Replace in Files starts, when you undo, and at the first start more than 7 days after the replace.
  • Backups are limited to 1 GiB in total. Files beyond that are still replaced, but without a backup, and can't be restored.
  • A file that has changed again since the replace is not restored. It is listed instead.

Regex flavours

WhereEngine
Find bar (current file), and Find in Files with the Current File and Open Files scopesJavaScript RegExp
Find in Files with the Folder or Choose… scopes, Replace in Files on disk, and large-file Find / Replace AllRust regex (the engine used by ripgrep): no look-around and no backreferences, but guaranteed linear-time matching

Everyday patterns (\d+, ^\s*$, (foo|bar), [A-Z]\w*) behave the same in both. Look-around ((?=…), (?<!…)) and backreferences (\1) work only in the JavaScript engine. Quarry checks a Find in Files pattern as you type, with the engine that will run it, and flags an invalid one: with Current File (on a normal tab) and Open Files a look-around pattern is accepted, while switching to Folder or Choose…, or making a large-file tab the current file, marks it invalid with the Rust engine's message.
