Benchmark results

Measured 24 November 2026.

Machine: Intel Core Ultra 7 265KF (20 threads), 32 GB RAM, NVMe SSD, Windows 11 Pro. App: Quarry release build of the code released as 1.0.0, default settings. Files: generated test files of 1 GB and 5 GB: a request log (59 million lines at 5 GB), a pretty-printed JSON array of records (321 million lines, 20 million records) and a CSV table (57 million rows). They had been read before, so they were in the Windows file cache.

The first pass over a file's mapping is slower than later ones: Windows has to map the file's pages into Quarry. In 1.0.0 the index did that pass, in 4 to 6 s; now the index, Find and the filter read the file with ordinary reads on up to eight cores and never pay it. JSON validation and the JSON tree's count still go through the mapping, and are about 2 s slower on a 5 GB file than in 1.0.0, where the index and earlier searches had already been through it. Checking the text encoding from disk first was tried and gave nothing back: the validator's own pass over the mapping took 6.9 s on its own, and the encoding check ahead of it was what had been warming it. The window timings use the find bar's and the filter's defaults (not case-sensitive).

Reading these numbers

  • One machine. A slower processor or disk gives slower numbers. On a hard disk or a network share the background line index takes longer; the first screen does not depend on it.
  • Warm cache. A file read for the first time after a restart comes straight from the disk. In October 2026 that made no measurable difference to opening on this SSD.
  • Large-file mode has fewer features than a normal tab: no multi-cursor, column mode or formatting. See Large files.
  • Replace All depends on the disk. It writes a working copy of the whole file, so a 5 GB file means 5 GB of writing. The times above are with Windows buffering those writes in memory, which is the usual case. When the drive had just taken tens of gigabytes of other writes, the same Replace All took 20 to 35 s, on any of the three file types.
